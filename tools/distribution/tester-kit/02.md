# Agent Road · 素材、验收与反馈
本包仅含合成样例，没有开发者的设备状态、账号、网络密钥或用户文件。

## 验收顺序
1. 记录两台机器系统/架构、已装工具、检测结果。区分未安装、不可见与不支持。
2. 登录和浏览器批准成功；whoami 为测试者自己的账号。
3. Windows 前置检查通过，一次配对。记录总耗时、各阶段耗时、人工操作次数、第一次失败的有限错误码。
4. list 选取本次设备 ID；status 为持久化记录，不能独立证明在线。运行 doctor、runtime-status，区分 SSH 可达与 RUNTIME_READY。
5. 用 exec 执行本包 smoke.ps1；核对退出码 0、PowerShell 版本、中文/emoji 输出。这是只读远程命令，不创建远程文件。
6. 经主人授权，在 `C:\AgentRoad-Work\` 下新建唯一测试子目录（禁止覆盖既有目录）。put 上传本包中文素材，get 到本地新文件；比对原始/返回字节数与 SHA256。不能只看命令退出 0。
7. job start 提交一次 smoke.ps1，立即保存 job ID；对同一 ID 查询 status，SUCCEEDED 且 exitCode 0 后取 logs 并核对内容。短任务可能直接终态，不要求看到 RUNNING。不要为观察 RUNNING 而重复提交。
8. 若功能回归通过，再测试网页入口：英文默认页、中文页、登录/注册/密码恢复入口、控制器授权页、下载与 Agent 指南链接。账号密码由主人输入；发送测试邮件和写账号状态需在测试者同意范围内。网页能打开不等于新机配对成功。

不把重启作为首轮必做项目：已有 VM 曾在正常重启时卡住，自动恢复未验收。GUI/浏览器自动化也不是标准 CLI 已保证的能力；不要抢焦点或干扰游戏。Mac→Mac、Windows→Windows 只反馈环境兼容性。

## 反馈方式
复制 feedback.md，给每一步填 PASS / FAIL / NOT_RUN / BLOCKED，加脱敏错误和耗时。先记录首次失败，不要一口气乱修；若做过修复，把修复步骤和第二次结果分开写。
不要发整个 AGENT_ROAD_HOME、完整 capture、密钥、登录 token、tailscale status 原文或用户文件。报告不自动发送；交给邀请你的测试发起者即可。
安装失败保留原 journal 与 operation/job ID 供本机核查。不可删除痕迹后重新安装、绕过 host-key 或身份校验。
