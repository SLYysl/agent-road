# Agent Road · 给 Agent 的中文提示词与用法
将三个包解压到同一个父目录。先复制「首次接入提示词」给控制端 Agent；其余段落按任务复制。不需要安装 skill 或调用另一个模型。

## 首次接入提示词（整段复制）
你正在帮助我进行 Agent Road 双机私人 Alpha 测试。请先找到我提供的 01-安装包、02-素材与反馈包、03-Agent中文提示词包，完整阅读 01/先读我.md、01/manifest.json、02/先读我.md 以及本文件。不要仅凭你对旧版 Agent Road 的记忆执行命令。先核验包内 SHA256；再阅读解压控制器的 docs/agent-interface.md、docs/agent-setup.md、docs/onboarding-status.json，确认命令契约和限制。底层英文接口文档用于核对参数，本次沟通、计划与反馈用中文。

先只读检查本机与目标机：系统/架构、管理员可用性、已有 Node/Git/Python、Tailscale/SSH/Agent Road 状态与待重启项。尚未连接时不要假称已检查远端：请目标机主人或其 Agent 运行包内检测，把脱敏结果带回。缺失与权限不足必须分开；报告「已有可复用 / 缺少 / 冲突 / 未知」，给出最小安装计划后再按主人授权继续。不要重装已有 Git、Node、Python；Mac Node >=22 优先直接运行本包控制器，无需 npm install。

当前可测试接入方向仅 Mac→Windows 11 x64。Mac→Mac、Windows→Windows 只做环境报告，不安装、不交换角色假装已支持。Windows 候选未签名、未完成第三方真机验收；这是明确选择的私人测试候选，不是公开稳定版。系统安全策略拦截时停止并记录，不关闭 Defender、不加排除、不降低执行策略、不移除下载标记。不要回退旧 bootstrap 绕过阻止。

使用独立私有 AGENT_ROAD_HOME，保留已有状态；本次所有命令使用相同的 home 和固定的控制器绝对路径。使用我自己的账号完成浏览器授权，核对代码；密码由我输入。使用我自己的 Tailscale 网络，通过本地隐藏输入保存单次 key，不在聊天、参数、日志或反馈里显示。不要使用开发者账号或尾网。缺少这些条件要明确停在哪一步，不能把旧设备的成功当成我的成功。

Windows 先准备前置依赖、解决需要主人批准的重启，再 native-preflight，通过后再创建短码。只调用本包固定哈希的原生 exe 和控制端显式 native-preview 命令。已有 SSH 配置、已登录的 Tailscale 身份、旧 AgentRoad root/journal 等冲突先停下诊断，不删除/注销/接管。账户批准不是重启或任意系统变更的授权；已得到的明确授权不重复询问。

配对后按 02 分别验收远程命令、core、文件哈希往返和后台任务。设备从当前 list 选择，不硬编码文档或聊天中的 ID；status 不是在线探测。任何调用结果不确定，保留原操作/任务 ID，查询原结果，不自动重放。一次只对同一设备执行一个控制器操作。现有设备功能回归、全新设备接入、网页入口验收要分开，不能互相替代。

先跑通直接发包流程，再试网页入口；完成后填写 02/feedback.md 的副本，明确通过、失败、未测、耗时、人工操作和最小下一步。不要发送原始凭据或自动向别人发报告。

## 命令速查
以下均接在 `node /实际路径/controller/src/cli.mjs` 后；若用附带 installer，则改用其生成的 bin/agent-road。动态参数用参数数组或正确引号，不把用户文字拼成 shell。

| 需求 | 参数 |
| --- | --- |
| 查看本地接口 | capabilities |
| 发现设备 | list / status <设备ID> |
| 在线诊断、运行时状态 | doctor <设备ID> / runtime-status <设备ID> |
| 短 PowerShell 脚本 | exec <设备ID> --script <本地绝对.ps1> --timeout-seconds 300 |
| 多脚本共享 SSH | session <设备ID> <绝对脚本1> <绝对脚本2> |
| 后台任务只提交一次 | job start <设备ID> <绝对脚本> 120 |
| 追踪原任务 | job status <设备ID> <任务ID> |
| 取原任务日志 | job logs <设备ID> <任务ID> |
| 请求取消 | job cancel <设备ID> <任务ID> |
| 注销终态调度定义 | job remove <设备ID> <任务ID> |
| 上传单文件 | put <设备ID> <本地绝对文件> <Windows绝对文件> |
| 下载单文件 | get <设备ID> <Windows绝对文件> <本地新文件> |
| 检查已有工具 | base-inspect <设备ID> |
| 使用检查过的工具 | base-exec <设备ID> <本次检查目录绝对路径> <绝对.ps1> node,python 300 |
| 测量命令耗时 | measure-exec <设备ID> 3 |

put/get 的远端路径使用 `C:\AgentRoad-Work\唯一任务名\文件.txt` 这种反斜杠绝对路径；先经授权新建父目录，不能传到保留的 C:\ProgramData\AgentRoad。默认不覆盖，覆盖需明确任务需要。这是单文件传输，不是目录同步。
session 最多 20 个脚本，复用 SSH 但不共享 PowerShell 进程/变量；遇到错误停止，勿整批重放。job 可脱离 SSH，不能保证跨重启续跑。cancel 受理不是已终止；继续查原 ID。remove 仅移除终态计划任务定义，保留日志/文件。
base-exec 的脚本通过 `& $AgentRoadTools.node ...` 或对应工具属性显式调用；不擅自换 PATH 工具。base-inspect 看见工具不代表已安装 managed base。

## 看结果和故障处理提示词
请保留此次失败的原操作 ID、job ID、capture 和有限错误，先检查原状态；不要通过重新提交来“验证”。普通 exec/put/get 为 JSON，job/session/base 多为 JSON lines，逐行解析。capture 是 Node os.tmpdir() 下目录名，原始内容私有，不直接发报告。job 的任务结果在 response.json 的 response.state.status/exitCode；控制命令退出 0 不等于任务成功。job logs 的 stdout/stderr 为 {offset,bytes,base64}，用 UTF-8 解码并说明是否仅尾部。
DEVICE_BUSY 先等待原操作结束；DEVICE_NOT_READY 先只读重查，不能推断上次脚本没执行。INTERRUPTED_OR_NOT_STARTED 也应检查同一任务 ID，避免完成状态竞态。主机密钥/身份冲突立即停止，不能跳过校验。安装阶段失败保留 journal 与原始错误，未知状态不能靠删除再装解决。core 不就绪按包内 agent-setup 的 readiness/baseline/recovery 流程调查，不凭 SSH 成功宣称完整运行时就绪。
