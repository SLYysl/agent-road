# Agent Road · 双机私人内测安装说明
版本：2026-09-23 / controller 59e025e / Windows build 11。

请将三个 ZIP 一起交给测试者。全部解压到同一个父目录，先阅读本文，再把 03 中的启动提示词交给有 Agent 的电脑。只下载本地包即可，不需要从网站下载安装器；浏览器账号授权和在线配对仍然保留。这不是完全离线安装包。

## 测试范围
- Mac → Windows 11 x64：本轮可尝试的接入方向。Mac arm64 已有本机安装证据，Intel 尚无执行验收。
- Mac → Mac、Windows → Windows：本轮仅环境检测和反馈，不安装、不声称已支持。
- 当前原生 Windows 安装器未签名。此前在一个新 VM 上完成配对和 core，尚未验证第三方真机首次安装；重启恢复曾卡住，不能承诺自动恢复。
- 本包是设备所有者主动选择的私人真机测试候选；manifest 不把它标记为公开发布或真机已验收。旧版英文文档的公开发行限制仍有效。本说明仅选择提供的固定哈希原生候选，不授权绕过系统安全拦截或尝试旧版安装路径。

## 第一步：两端只读检测
Mac 上用 bash 运行 inspect-mac.sh；Windows 上在 PowerShell 阅读并运行 inspect-windows.ps1。脚本仅观察，不安装、不重启、不修改服务。脚本被策略阻止时记录错误，停止；不要降低执行策略。管理员不可用时 UNKNOWN 不代表缺失。

检查系统、架构、管理员能力，Git/Node/Python、Tailscale、OpenSSH、旧 Agent Road 状态和待重启项。反馈时隐藏用户名、设备名、网络地址。
Windows 的已有 Git/Node/Python 无需重装；本轮 core 接入不要求安装这些工具。已有运行中的 SSH、非空 C:\ProgramData\ssh、已有 AgentRoad 目录/账号，或者已登录的 Tailscale 身份，都需要停止并反馈冲突；当前候选不负责迁移接管，不要删除/注销它们。

## 第二步：Mac 控制器，优先复用现有 Node
先核验 SHA256SUMS.txt。Mac 可运行 `shasum -a 256 -c SHA256SUMS.txt`；Windows 对 exe 用 `Get-FileHash .\AgentRoadNativeSetup.exe -Algorithm SHA256`，和 manifest 比较。
已有 Node >=22：将 agent-road-controller.tar.gz 解压到新建目录，用 `node /绝对路径/controller/src/cli.mjs capabilities` 验证。运行时无 npm 依赖，不需要 npm install、不需要 Git、不需要全局 npm 安装。

为本次测试设置独立且私有的 AGENT_ROAD_HOME（目录 0700，文件 0600），所有命令均使用相同值；不要复制其他人的控制器状态。确认目录是新建且不覆盖原有目录。以下命令中的 AR_CLI 指向解压后的 src/cli.mjs；所有占位路径由 Agent 替换为实际绝对路径。

若 Node 缺失或版本不符，取得用户对本地私有安装的同意后，使用附带 install.sh，设置 AGENT_ROAD_ARCHIVE_FILE 为本包 archive 的绝对路径，并设置 AGENT_ROAD_INSTALL_PREFIX 为新的用户私有安装目录。安装器仍从 nodejs.org 下载官方私有 Node，不替换系统 Node；不得用 sudo。用其生成的 bin/agent-road 启动，替代后续的 node "$AR_CLI"。

## 第三步：账号与测试者自己的网络
运行 `node "$AR_CLI" login`，或 `login --no-browser`。测试者自行注册/登录、验证邮箱、核对 CLI 和网页代码后批准；Agent 不索取密码。再执行 whoami，核对自己的账号。
Mac 要有已登录的 Tailscale、.ts.net 名称和 Serve 权限；读取 status 与 serve status。缺依赖先说明安装计划并由设备主人同意，不重置已有网络或 Serve 路由。

在私有 AGENT_ROAD_HOME/pairing.json 写入：
```json
{"origin":"https://agent-road.brahma-technologies.com","tailscaleAuthKeyFile":"/实际私有绝对路径/tailscale-auth-key"}
```
测试者在自己的 Tailscale 后台生成单次 auth key（tskey-auth-），通过本地隐藏输入写入所指文件，文件 0600；不要粘贴到聊天、命令参数或报告。不能使用开发者的网络密钥。也可使用 tailscaleApiTokenFile 指向自己的 tskey-api-，二选一。账号模式不需要共享 admin token，不要用 --config 绕过账号授权。
单次密钥被消耗后不得再次使用；结果不确定先检查原尝试，再决定后续动作。

## 第四步：Windows 先准备，再生成短码
使用管理员终端核验 exe 哈希，然后执行：
```powershell
.\AgentRoadNativeSetup.exe --inspect
```
仅在检测确认缺少相应依赖、且主人同意变更后，按需执行：
```powershell
.\AgentRoadNativeSetup.exe --install-openssh --accept-system-changes
.\AgentRoadNativeSetup.exe --install-tailscale --accept-system-changes
```
不要重复执行已有安装尝试；保留 journal，先诊断。Windows 更新或依赖要求重启时先取得主人允许，准备完后再生成短码，避免邀请过期。不要自动重启正在使用的电脑。
然后运行 `AgentRoadNativeSetup.exe --native-preflight`。必须通过后才继续。若 Defender、SmartScreen 或组织策略阻止，保留错误并停止，不关闭保护、不加排除、不移除下载标记、不降低策略。

## 第五步：一次原生配对
Mac 保持交互终端运行：
```sh
AGENT_ROAD_NATIVE_PREVIEW=1 node "$AR_CLI" pair --native-preview --name "My Windows PC" --timeout-minutes 15
```
将此次输出的 12 位短码交给 Windows 主人；不要使用文档里的示例值。在 Windows 管理员终端运行：
```powershell
.\AgentRoadNativeSetup.exe --pair 本次短码 --accept-system-changes
```
主人检查变更并按终端提示确认，双方核对 8 位验证代码，按交互提示继续。安装器将创建专用管理员账号、配置受限 SSH/防火墙并加入所选网络，这是实际系统变更；主人应事先知情。不要使用普通 pair 回落到旧 PowerShell bootstrap。
失败或超时保留原尝试及回执，不盲目新建短码/重放安装。成功也需要 02 的逐项验收。

## 测试后
接入建立了持续的远程管理能力。暂时不用时可由主人正常关闭设备或用自己网络的管理功能撤销该设备连接；这不等于完整卸载。当前包不提供已验收的一键卸载/回滚，不手动删除 journal、账号、密钥或系统 SSH 配置。需要彻底撤销时先反馈并制定针对该设备的清理计划。
